# audit9：iPhone向け戦闘UI・1画面化

## 実装内容
元のaudit8を保持し、別ディレクトリのaudit9で戦闘表示だけを変更しました。
- 実際のvisualViewport高さに合わせて戦闘画面を割り当て、上部・状態欄・コマンド・戦場の表示領域を確保。アドレスバーの表示変化はresizeで追従。
- 通常戦のコマンドは2列＋下段全幅必殺。羽撃ち分け時の穿羽・連羽も同時表示し、防御は右列を維持。
- 戦場は敵・味方の2段構成。左右を画像とHP専用領域に分け、物理的な重なりを解消。絵柄はcontainで縦横比を維持。
- 通常/EXカイザーの参照を既存の透過WebP/PNGへ統一。元のJPEG素材も削除していません。
- 提供5アイコンを採用。穿羽・連羽も羽弾アイコンを共有。元PNGはバイト同一で保存し、表示用WebPだけ384角/必殺768×256へ縮小・ロスレス保存。透明度を保持。PNGはパレット透過(tRNS)でした。
- 詳細能力/状態と戦闘ログはボタンでダイアログ表示。戦闘コマンドを隠さず、必要時だけ詳細を開けます。短い表示領域の状態文は省略表示になり得ますが、詳細ダイアログで確認できます。
- 戦闘中の下ナビ・サイドナビ・補助ナビは非表示。勝敗・撤退後は従来どおり復帰。
- PWA相当の上下セーフエリアを考慮。PWAインストール機構やService Workerの新設はしていません。

## 変更範囲
既存コードは web/src/components/App.js（アイコン・透過画像参照・詳細ダイアログ・viewport連動）とgame.css（戦闘時の表示）に限定。
ほかに追加素材assets/combat-ui-audit9、tests/compact-ui.test.js、既存厳密スナップショット照合の追加層tests/audit-baseline.js、案内READMEと今回のレポートを追加・更新。
戦闘エンジン、倍率、敵AI、報酬、20階進行、EX/ステラ/専用いれーな、刻印/権能/共鳴、B案、保存処理・キー・形式は変更していません。これらのファイルはaudit8とのハッシュ一致を検査しています。
添付ZIPの原本と参考画像はcombat-ui-user-inputに保持。元のaudit8は上書きしていません。

## 表示検証
Chromiumのタッチ/モバイル設定で、320×480、375×548、390×664、430×740、390×844を検証。最後はPWA相当として上47px・下34pxを予約して確認。
通常コマンド5個と羽撃ち分け装備時6個について、全ボタンの上下座標がviewport内、44px以上、ページ縦横スクロールなし、立ち絵とHP欄の分離、HP枠がカード内に収まること、画像デコードを検査。実際の斬撃1ターン・詳細/ログ開閉・撤退後のナビ復帰も操作。
EX/ステラと、神化100まで進めた専用いれーなでも、解放中の全コマンドが画面内に収まることを確認。最終119項目成功・ページエラー0件。詳細はbrowser.json。
最小サイズでは立ち絵が小さくなります。タッチコマンドの実用サイズとHPの可読性を優先しています。Safari/PWA/iPhone実機での実測ではなく、サイズ・セーフエリアを模擬した検証です。ブラウザの文字拡大・横画面は今回の保証範囲に含めません。

## テスト・ビルド
変更前：既存334テスト/check49/build成功。
追加3テストを含む全体337テスト成功。最終表示修正後はcompact UI・既存戦闘UI・B案の関連14テストを再実行し全件成功。構文チェック50ファイル成功。既存テストは削除・緩和していません。許可された表示差分の前後両方のハッシュを照合してから、従来の厳密なスナップショット条件へ渡しています。

同じ透過立ち絵のデータURL重複埋め込みも避け、単体HTMLを約24MBに抑制。画像を新規生成・描き直し・背景処理していません。
