# いれーな REBORN — Codex向けバトルUI改修 指示書

この指示書は、Codexに **かなり自走して** 進めてもらう前提で作成しています。
ただし、闇雲な大改造ではなく、**現在のゲームの魅力・既存仕様・保存互換を守りながら、スマホ向けの通常戦闘UIを大きく改善する** ことが目的です。

---

## 0. 今回の目的

目的は、**スマホ向け通常戦闘UIの本格改善** です。

ユーザーは、最終決戦のような重厚でドラマチックな方向性はかなり気に入っています。一方で、**通常戦闘はもっと見やすく・わかりやすく・毎回遊びやすく** したいです。

今回の依頼では、以下を重視してください。

1. **スマホ縦画面での視認性**
2. **一目で理解できる戦闘情報整理**
3. **既存仕様をできるだけ維持したままUIだけを大きく改善**
4. **AIっぽすぎる過剰な装飾感を避ける**（雑・手作り感ではなく、少し大づかみで自然な画面）
5. **必要ならCodexが自分で調査・比較・軽い設計提案を行ってから実装**

## 2. 重要な前提・厳守事項

### 2-1. これは「通常戦闘UI」中心の改善
今回は、**通常戦闘をどう見せるか** が主題です。
最終決戦向けの大きな演出路線をそのまま通常戦闘へ持ち込みすぎないでください。

### 2-2. 攻撃予測UIは不要
これは過去に失敗した要素なので、**攻撃予測・次行動予測・ダメージ予測・未来表示UIは追加しないでください。**

### 2-3. 既存仕様の保護を優先
ユーザーが明示していない戦闘ルール・報酬・進行・保存形式を、勝手に大きく変えないでください。
特に以下は保護優先です。

- セーブ互換
- 解放順序
- 成長・報酬の大枠
- 既存の権能や刻印の基本仕様
- 実験場・本編の既存導線

### 2-4. スマホ最優先
PCの見た目より、**iPhone相当の縦画面** で使いやすいことを優先してください。
最低でも以下の幅で見てください。

- 320px
- 375px
- 390px
- 430px

## 3. 今回やってほしいこと（実装タスク）

### タスクA. 通常戦闘UIの見直し
通常戦闘の戦闘画面を、スマホ向けに見やすく再構成してください。

目標:
- 画面がごちゃつきすぎない
- 重要情報の優先順位が明確
- キャラの雰囲気は保ちつつ、毎ターン見ても疲れにくい
- 「AIが細かく盛りすぎた感」を減らす

方向性:
- 参考画像 `battle-ui-target-normal.png` の空気感・構図・密度感をベースにしてよい
- ただし、**そのまま全面コピーするのではなく、ゲームとして使いやすい構造へ落とし込むこと**
- 背景や装飾は少し大づかみにし、UI可読性を優先
- 下部コマンド周辺は過密にしない

### タスクB. HPゲージ色の調整
**いれーなのHPゲージは緑系の方が良い** と考えています。

実装方針:
- プレイヤー側HPゲージは緑系へ寄せる
- 敵HPゲージは現状のままでもよいが、視認性バランスを見て必要なら微調整可
- ただし、過度に派手なグラデーションにしない

### タスクC. 羽弾 / 穿羽 / 連羽の表示ルール整理
ここはかなり重要です。

ユーザー意向:
- **穿羽と連羽がある時は、羽弾は出てこないようにしたい**
- つまり、同時表示ではなく **どちらか** にしたい

現在認識している前提:
- 条件は「刻印」ベース
- 既存実装では、`split` 系の刻印条件で穿羽・連羽が出る仕組みがある可能性が高い
- ただし現状は羽弾も残っている可能性がある

実装したい仕様:
- **対応する刻印を装備していない時** → `黒翼・羽弾` を表示
- **対応する刻印を装備している時** → `穿羽` と `連羽` を表示し、`黒翼・羽弾` は表示しない

注意:
- これは「表示だけ差し替え」なのか「コマンド構成そのものの差し替え」なのか、ソースを見て自然な方で実装してください
- ゲージ獲得・CT・既存バランスへの影響を必ず確認
- 条件が実際には刻印名 `split` 以外なら、正しい既存条件に合わせてください

### タスクD. 「防御」の意味をわかりやすくする
ユーザーから「防御って何？」という感想が出ています。
これは機能が弱いという意味ではなく、**プレイヤーから見て説明不足・意味が伝わりにくい** という課題です。

やってほしいこと:
- 現在の `防御` の実際の挙動を確認
- 表示名・サブテキスト・補足文などで、**何が起きる技なのか一目で伝わるように改善**

重要:
- 防御の中身を勝手に大きく変えるより、まずは **伝わり方の改善** を優先
- もし仕様上わかりにくさが深刻なら、**最小限のUI/文言改善** を提案・実装してよい
- 例: 「被ダメ軽減」「ゲージ増加」などが伝わる形にする

### タスクE. 不要・過剰な要素を抑える
以下の方向で整理してください。

- 過密な装飾や過剰な小情報は減らす
- 戦闘に不要な英字ラベルや雰囲気優先の情報が可読性を下げているなら整理
- ただし、世界観を壊すほど素っ気なくしない

## 4. デザイン方針

### 4-1. 通常戦闘の理想
通常戦闘は以下を目指してください。

- 一目で「今どういう状況か」がわかる
- 毎ターン見ても疲れにくい
- スマホで親指操作しやすい
- 雰囲気はあるが、UIが情報に負けない

### 4-2. 最終決戦との差別化
最終決戦は、多少演出寄り・豪華寄りでもOKです。
通常戦闘はそれよりも、**実用性寄り** にしてください。

### 4-3. 「AIっぽさ」を減らす
ここでいうAIっぽさとは、以下です。

- 無駄に情報が多い
- 細部を盛りすぎて逆に読みづらい
- それっぽいが、ゲーム画面としては疲れる

したがって、**良い意味で少し大雑把に・整理して・実用的に** してください。

## 5. Codexに任せたい姿勢（自走歓迎）

今回は一気にかなり自走して構いません。

期待する進め方:
1. 現状の戦闘UIとコマンド生成ロジックを確認
2. 羽弾/穿羽/連羽/防御の現在実装を確認
3. スマホ通常戦闘UIの改善案を整理
4. 必要な範囲でコード修正
5. 画面確認・テスト
6. 変更点と理由をレポート

ただし、**「勝手に別ゲー化する自走」はNG** です。

良い自走:
- 必要な箇所を自分で見つける
- 画面とロジックのつながりを整理する
- 小さな改善をまとめて仕上げる

ダメな自走:
- 無関係な大改造
- 保存形式やバランスを勝手に大きく変更
- 依頼されていない予測UIの追加

## 6. 変更してよい範囲 / よくない範囲

### 変更してよい
- 通常戦闘UIのレイアウト
- 見出しやラベル
- HPゲージ色
- コマンドの表示条件整理
- 防御の説明文・サブテキスト
- 必要な軽微なスタイル調整

### 原則変更しない
- セーブ形式
- 本編進行順
- 報酬や成長の大枠
- 既存の重要戦闘ルール
- ユーザーが不要と言っている攻撃予測UI

### 変更するなら必ず説明
- 防御の中身
- 羽弾/穿羽/連羽のロジック
- スキル性能へ波及する変更

## 8. 最後に必ず書いてほしいこと（重要）

レポートの最後に、**「追加で欲しい画像」** セクションを必ず入れてください。

そこには、今後さらに良くするために必要だと思った画像素材を、**具体的に** 書いてください。

書き方の例:
- どの画面用か（通常戦闘 / 最終決戦 / ホーム / カットイン など）
- 何の画像か（背景、カード絵、バナー、敵立ち絵、アイコンなど）
- 枚数
- 望ましい縦横比
- 透過が必要か
- どういう雰囲気がほしいか

曖昧に「画像が欲しい」ではなく、**Codex側が本当に必要だと思った素材一覧** を出してください。
