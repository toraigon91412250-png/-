# レイドプロジェクト01：アビスコア

このフォルダは、Web版の独立レイド試作品を置く場所です。本編の1対1戦闘エンジンとは意図的に分離しています。

## 構成

- `types.ts`: レイド専用の状態、行動、結果の型。
- `engine.ts`: 行動コスト、攻撃予告への回答、ダメージ、BREAK、形態変化、スコア計算を行う状態遷移関数。ランダム関数を引数で受け取れるため、テストで動作を再現できます。
- `RaidGame.tsx`: 行動選択、HP/MP/TP、ボス予告、演出、戦闘結果、ローカルベストスコアを表示する画面。
- `raid.css`: 本編の画面スタイルに依存しないレスポンシブUIと演出。

Appとメニューは入口だけを担当します。レイドエンジンから本編の `useBattleGame`、`battleMath`、`abilitySystem`、成長データ保存を呼び出しません。

## 現在のゲームループ

1. ボスの次の行動予告を読む。
2. 行動を一つ選び、プレイヤー行動とボスの反撃を1回の状態遷移で処理する。
3. 滅界砲・終焉衝動には迎撃、虚無落雷には羽弾を合わせると、攻撃を止められる。
4. 攻撃や正しい回答でBREAKを蓄積し、BREAK後の一手で大ダメージを狙う。
5. 第1形態を撃破すると深淵解放へ移行する。
6. 第2形態は同じ行動の連続に適応するため、選択を変えて圧力を下げる。

## 第2回での調整内容

- 防御のMP消費を10、回復量を80に調整。大技への防御は軽減率50%・固定軽減300にし、被害を抑えつつも、正しい迎撃の「攻撃を完全に止めて反撃する」価値を残す。通常予告への防御は軽減率65%・固定軽減220を維持。
- 集中はMP8、TP+32、次のダメージ倍率1.65倍に加え、集中したターンの被ダメージを倍率0.7・固定軽減120で軽減する。大技では専用防御や迎撃より危険を残すため、準備と生存の中間的な選択肢になる。
- 予告パネルに推奨行動を表示。集中効果が残っている間は「FOCUS READY」と倍率を画面に表示する。
- 戦闘履歴を最大5手分記録し、各手の行動、結果、与ダメージ、被ダメージ、MP変化を確認可能にした。勝敗画面には6行動の使用回数も表示する。
- テストに、4種類の予告 × 6行動の24ケース、資源不足、各種ステータスの範囲、集中倍率、防御と迎撃の報酬差、および30シードずつの行動方針シミュレーションを追加した。
- レイド専用のRAID_RULESとUIに限定した変更。本編の戦闘ロジック、セーブキー、本番設定には接続・変更しない。

## データ境界

- ベストスコアには専用キー `raidPrototypeV1BestScore` を使用。本編の成長・権能・召喚データは変更しません。
- 旧 `raidBossBestScore` は読み書きしません。
- 旧 `RaidBossScreen.tsx` と関連素材は比較・再利用用にリポジトリへ残しています。現在のWeb版のレイド画面には使用しません。
- 数値は試作バランスであり、本編のキャラクター設定値そのものではありません。

## 5回の開発計画

### 第2回（今回実施）
- 防御と集中の数値を調整し、6行動すべてに用途が見える状態を目指した。
- 予告ごとの推奨行動、集中状態、直近5手の履歴、結果時の行動回数を追加。
- 24ケースの行動・予告マトリクスと30シード×3方針の比較、各行動の平均使用回数、集中時の被ダメージ軽減を追加。最終CIの集計値をPR報告に記載する。

### 第3回（大規模な戦闘機能の実装）
- ボス行動「崩壊連撃」を複数ターンの予兆→発動直前→解決として状態管理する。準備ターンは被害を発生させず、次ターンに迎撃すれば攻撃を無効化できる。失敗時は大きな被害を受ける。
- ボス行動「虚核再生」を追加。対応しなければ最大700 HPを回復し、羽弾による詠唱妨害で回復を防げる。
- 第2形態の行動候補に両ギミックを追加し、既存6行動に新しい攻略機会を持たせる。
- 戦闘状態にマルチターン予告、妨害成功回数、回復阻止量を記録。戦闘履歴・リザルトに表示する。
- 固定シードのルールテストを36ケース（6行動×6予告）に拡張し、再生妨害、回復量上限、連撃準備、迎撃成功、失敗時被害を検証する。PlaywrightでPC・スマホの両方から再生妨害と第2形態の連撃を実際に操作する。

### 第4回（バグ・UI・操作性）
- 新機能を原則凍結して、再現性のあるバグ、表示崩れ、スマホ操作、予兆の分かりやすさ、戦闘履歴、フェーズ移行、終了後の入力を修正する。
- テストで見つかった本編への影響や既存動作の回帰も確認する。不要な機能は本番へ取り込む前に削除・縮小を検討する。

### 第5回（最終バランス）
- 大きなルール変更を止め、HP/MP/TP、攻撃威力、回復量、BREAK、再生頻度、崩壊連撃の猶予・被害、適応速度、スコアを調整する。
- 100以上の固定シードを用いた複数方針のシミュレーション、全ルールテスト、型チェック、本番ビルド、PC/スマホE2Eを再実行する。

### 変更境界
- 主な編集対象は web/src/raid/、web/test-rules.js、web/e2e/combat-regressions.spec.ts。メニューとAppは入口の変更が不可欠な場合に限り触る。
- 本編の戦闘エンジン・成長・権能・召喚・既存セーブ形式・Android・本番デプロイ設定は、別途必要性が証明されない限り変更しない。
- mainへマージする前にPR差分を確認し、ルールテスト、TypeScript/Viteビルド、全E2Eが成功していることを必須とする。


## 第3回で追加した戦闘ルール

- CORE_REGEN（虚核再生）はプレイヤーの攻撃後に発動する回復行動で、プレイヤーへ直接ダメージは与えない。羽弾で阻止した場合、阻止量を記録する。
- COLLAPSE（崩壊連撃）は bossWindup: 0 の準備状態と bossWindup: 1 の発動直前状態を持つ。準備状態では攻撃せず、発動直前に迎撃すれば攻撃を止める。
- 新ギミックはレイド専用状態とエンジンの中で処理し、本編の戦闘計算やセーブデータとは共有しない。
